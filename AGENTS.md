# ux-expert: instructions for AI coding agents

This file is the single entry point for any AI coding agent (Claude Code, Codex,
Cursor, Copilot, Gemini CLI…) working in this repository. Human contributors
read it too. Tool-specific files (`CLAUDE.md`, `.cursorrules`…) only import this
file and add what is specific to that tool.

---

## 1. Read before you write

1. Read this file, then `CONTRIBUTING.md`, then the guides that apply:
   - `docs/engineering/principles.md`: rules for all code (scripts, MCP server);
   - `docs/engineering/content.md`: rules for skill content (criteria, areas,
     references), which is most of this repository.
2. Read the story (`UXE-<n>` in `docs/backlog/`) in full: why, decisions,
   acceptance criteria, out of scope.
3. Check the story's dependencies are merged into `develop`. If one is not,
   **stop and say so**.
4. Search for what already exists (a criterion, a reference, a script) before
   you create anything. Reuse beats reinvention.
5. For a specification or library you are not sure about (Agent Skills spec,
   MCP spec, an SDK), read its current source or docs instead of trusting
   memory of an older version. Clone public repositories to read them when
   needed; record the version or commit you relied on in the PR.

## 2. Project overview

- **Product:** an expert UX knowledge package for AI agents. It lets any agent
  design, refactor and audit a product's user experience the way a principal
  UX engineer would: user goals first, evidence for every finding, consistent
  severity, and a launch verdict.
- **This repository:** the source of the `ux-expert` Agent Skill (open
  [Agent Skills](https://agentskills.io) format) and, from v0.3, the MCP server
  and single-file bundles built from the same source.
- **Stack:** Markdown + YAML content; Python 3.12 (standard library first) for
  validation and generation scripts; TypeScript (Node.js LTS) for the MCP
  server. Keep dependencies on the latest stable, mutually compatible versions.
- **Source of truth for scope:** `docs/backlog/README.md`.
- **Architecture decisions:** `docs/adr/`.

## 3. Hard rules (non-negotiable)

1. **No AI authorship trace, anywhere.** No commit message, PR title or body,
   code comment, file header or document may mention "AI", "Claude", "Copilot",
   "ChatGPT", "generated by" or any equivalent as the *author* of the change,
   and no `Co-authored-by` line for a tool. Write as the engineer who owns the
   change. (Naming AI agents as the *audience or subject* of the package, as in
   this file, is fine.)
2. **Conventional Commits** with a ticket trailer:
   `<type>(<scope>): <description>` + blank line + body + `Refs: UXE-<n>`.
   Types: `feat`, `fix`, `refactor`, `test`, `docs`, `chore`, `perf`, `build`.
3. **One story, one branch, merged before the next.** Branch
   `uxe-<n>-<slug>` from an up-to-date `develop`; squash-merge into `develop`;
   never stack a story on an unmerged one; never commit to `main` or `develop`.
4. **Criterion IDs are permanent.** A published ID (e.g. `FORM-09`) never
   changes meaning and is never reused. Retire it (`status: retired`) instead.
5. **Every number has a source.** A threshold, statistic or research result in
   the content cites where it comes from. An estimate says it is an estimate.
6. **One source of truth.** Shared references and criteria exist once; anything
   derived (tables, bundles, MCP resources) is generated, never hand-copied.
7. **Spec compliance.** Every skill passes `skills-ref validate`; `SKILL.md`
   stays under 500 lines; files referenced from `SKILL.md` use paths relative
   to the skill root.
8. **No dead content.** What your change leaves unused (files, references,
   criteria rows, scripts) is deleted or retired in the same change.
9. **Stop at an `[INTERACTIVE STEP]`** or any decision that belongs to the
   product owner: present the options with a recommendation and wait.
10. **Additive changes on a published version.** A breaking change to the skill
    layout, criterion schema or MCP interface means a new major version and a
    migration note in `CHANGELOG.md`.

## 4. How to work (agent behaviour)

- **Small, verified steps.** Change, run the checks, look at the result, then
  continue. One validated push beats three speculative ones.
- **Prove it works, then say so.** Run the checks in section 5. For content
  changes that alter agent behaviour, say which eval or manual run you used to
  confirm it (from UXE-10 onward, run the evals).
- **Report honestly.** If a check fails, say which and why. If something was not
  verified, say it was not verified.
- **Not overkill.** Add what an agent would get wrong without it; cut what it
  already knows. Moderate detail with a clear default beats exhaustive menus.
- **Ask when it matters, decide when it does not.** Ask about product
  decisions and outward-facing actions (publishing, releasing, licensing).
  Decide conventional technical choices yourself and say what you chose.
- **Leave it better than you found it, within scope.** Note the rest as a
  follow-up story instead of widening the PR.

## 5. Checks before every push

```bash
python3 -m unittest discover -s scripts -p "test_*.py"  # validator tests
python3 scripts/validate.py                              # repo rules: IDs, links, budget
skills-ref validate skills/ux-expert                     # Agent Skills spec compliance
```

`skills-ref` is installed from the pinned commit in
`.github/workflows/ci.yml`. CI runs the same commands and blocks the merge
when one fails. To install `skills-ref` locally:
`pip install "skills-ref @ git+https://github.com/agentskills/agentskills@<commit>#subdirectory=skills-ref"`
with the commit from the workflow.

## 6. Pull requests

- Title = the squash commit title (Conventional Commits).
- Body follows `.github/pull_request_template.md`.
- Open as **draft** while work is in progress; mark ready when CI is green.
- Every review comment gets an answer: fixed (with the commit), or why not.

## 7. Releases

- `develop` → `main` through a release PR merged with a **merge commit**.
- Each release bumps the version in `skills/ux-expert/SKILL.md` metadata and
  `.claude-plugin/marketplace.json`, updates `CHANGELOG.md`, and is tagged
  `vX.Y.Z` on `main`.
- Releasing is outward-facing: it happens only when the maintainer asks.
